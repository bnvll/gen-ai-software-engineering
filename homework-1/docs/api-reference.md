# Banking Transactions API — API Reference

> Version 1.0.0 · In-memory demo API built for homework 1 of the *GenAI and Agentic AI for Software Engineering* course.

The Banking Transactions API records money movements between accounts and derives
account-level figures (balance, activity summary, projected interest) from that
ledger. It is deliberately small: one resource (`transaction`), one derived
resource (`account`), no database and no authentication.

The structure of this reference follows the layout used by production core-banking
API documentation — [Qonto Business API](https://docs.qonto.com/) and
[Solaris](https://docs.solarisgroup.com/) — because those docs make the
*conventions* explicit before listing endpoints: standards first, errors second,
endpoints last.

## Getting started

| | |
|---|---|
| **Base URL** | `http://localhost:3000` |
| **Content type** | `application/json` (required on `POST`) |
| **Authentication** | none — this is a local demo API |
| **Storage** | in memory; restarting the process empties the ledger |

```bash
# start the API with the demo ledger preloaded
./demo/run.sh

# create a transfer
curl -X POST http://localhost:3000/transactions \
  -H "Content-Type: application/json" \
  -d '{
    "fromAccount": "ACC-12345",
    "toAccount": "ACC-67890",
    "amount": 100.50,
    "currency": "USD",
    "type": "transfer"
  }'
```

`GET /` returns a machine-readable index of every endpoint and enum, which is the
quickest way to explore the API from a terminal.

## Standards

### Requests and responses

- Every response body is JSON, except `GET /transactions/export?format=csv`.
- `POST` requests **must** send `Content-Type: application/json`; anything else is
  rejected with `415 Unsupported Media Type` instead of being silently parsed as
  an empty body.
- Request bodies are limited to 64 kB.
- **Unknown fields in a request body are ignored**, and so are unknown query
  parameters. This keeps clients forward-compatible: sending a field this version
  does not know about is never an error.
- Server-owned fields cannot be set by the client. Sending `"id": "my-id"` is
  ignored — ids are always generated by the server.
- A query parameter may appear **at most once**. `?type=deposit&type=transfer` is
  rejected rather than silently collapsed into one value.

### Account numbers

Accounts are identified by the string format `ACC-XXXXX`, where each `X` is one
alphanumeric character:

| Value | Result |
|---|---|
| `ACC-12345` | valid |
| `ACC-A1B2C` | valid |
| `acc-12345` | valid — normalized to `ACC-12345` |
| `ACC-1234`, `ACC-123456` | invalid (must be exactly 5 characters) |
| `ACCT-12345`, `12345`, `ACC_12345` | invalid |

Account numbers are compared case-insensitively and stored upper-cased, so a
balance never splits across two spellings of the same account.

There is **no account resource**: an account exists as soon as it appears on
either side of a transaction. Requesting an account that no transaction
references returns `404`.

### Money and currencies

- An amount is always paired with a currency, and **amounts in different
  currencies are never summed**. Every balance, total and interest figure is
  reported per currency.
- Amounts must be positive JSON numbers with at most **2 decimal places**.
- Precision also follows the currency's ISO 4217 minor unit: `100.50 USD` is
  valid, `100.50 JPY` is not, because the yen has no minor unit.
- Internally amounts are stored as integer minor units (cents) and only
  converted back to decimals in the response, so summing cent amounts cannot
  drift (`0.1 + 0.2` really is `0.3`).
- Supported currency codes: `AED AUD BGN BHD BRL CAD CHF CNY CZK DKK EUR GBP HKD
  HUF IDR ILS INR ISK JPY KRW KWD MXN MYR NOK NZD PLN RON SAR SEK SGD THB TRY USD
  ZAR`. Codes are accepted in any case and normalized to upper case. `GET /`
  returns the authoritative list.

### Dates and times

All timestamps are ISO 8601 and are stored and returned in UTC
(`2024-01-15T10:30:00.000Z`).

| Input | Interpreted as |
|---|---|
| `2024-01-15T10:30:00Z` | that instant |
| `2024-01-15T12:30:00+02:00` | `2024-01-15T10:30:00Z` |
| `2024-01-15T10:30:00` | `2024-01-15T10:30:00Z` — a missing offset means UTC, never server-local time |
| `2024-01-15` | `2024-01-15T00:00:00Z` (as a filter boundary, see below) |
| `2024-02-31`, `15/01/2024` | rejected — the first is not a real date, the second is not ISO 8601 |

In `from` / `to` filters a bare calendar date covers the **whole UTC day**:
`?from=2024-01-01&to=2024-01-31` includes a transaction emitted at
`2024-01-31T23:59:59Z`. Both bounds are inclusive.

### Ordering

Transaction lists are returned **newest first** (by `timestamp`, descending).
Transactions sharing a timestamp are returned most-recently-created first.

### Transaction status and money movement

`pending`, `completed` and `failed` transactions are all stored and listed, but
**only `completed` transactions move money**. Balances, summary totals and
interest are computed from completed transactions alone; `GET
/accounts/:accountId/summary` reports the excluded ones under
`statusBreakdown`.

## Errors

Two error shapes are used, both always JSON.

**Field-level validation errors** (`400`) list every problem in the request at
once, so a client never has to fix one field at a time:

```json
{
  "error": "Validation failed",
  "details": [
    { "field": "amount", "message": "Amount must be a positive number" },
    { "field": "currency", "message": "Invalid currency code. Use a supported ISO 4217 code (e.g. USD, EUR, GBP, JPY)" }
  ]
}
```

**Everything else** carries a short label and a human-readable message:

```json
{
  "error": "Not found",
  "message": "Account ACC-99999 not found. No transaction references this account"
}
```

| Status | `error` | When |
|---|---|---|
| `400` | `Validation failed` | A body field or query parameter is invalid. `details` lists the offending fields. |
| `400` | `Bad request` | The request cannot be answered as sent — malformed JSON, a missing request body, or an ambiguous multi-currency request that needs `?currency=`. |
| `404` | `Not found` | Unknown transaction id, unknown account, or unknown route. |
| `413` | `Payload too large` | The request body exceeds 64 kB. |
| `415` | `Unsupported Media Type` | `POST` without `Content-Type: application/json`. |
| `429` | `Too Many Requests` | The rate limit was exceeded. See [Rate limits](#rate-limits). |
| `500` | `Internal server error` | Unexpected server-side failure. Details are logged, never returned. |

Field names in `details.field` match the request: body fields use their JSON name
(`amount`, `fromAccount`), query parameters use their parameter name (`from`,
`type`), and `accountId` is used for the path parameter of the account endpoints.

## Rate limits

A fixed window of **100 requests per minute per client IP** applies to every
endpoint (Qonto and Solaris apply comparable per-caller limits; the numbers here
come from the assignment).

Every response carries the current budget:

| Header | Meaning |
|---|---|
| `X-RateLimit-Limit` | requests allowed per window |
| `X-RateLimit-Remaining` | requests left in the current window |
| `X-RateLimit-Reset` | seconds until the window resets |

Exceeding the limit returns `429` with a `Retry-After` header:

```json
{
  "error": "Too Many Requests",
  "message": "Rate limit of 100 requests per 60s exceeded. Retry in 47s",
  "retryAfterSeconds": 47
}
```

The limiter is configurable and can be switched off for load testing — see
[HOWTORUN.md](../HOWTORUN.md#environment-variables).

## The transaction object

```json
{
  "id": "adf95890-ed34-4247-a4f3-d6dfa7c543da",
  "fromAccount": "ACC-12345",
  "toAccount": "ACC-67890",
  "amount": 100.5,
  "currency": "USD",
  "type": "transfer",
  "timestamp": "2024-01-05T14:20:00.000Z",
  "status": "completed"
}
```

| Field | Type | Description |
|---|---|---|
| `id` | string (UUID v4) | Server-generated identifier. Read-only. |
| `fromAccount` | string \| null | Debited account (`ACC-XXXXX`). `null` for deposits. |
| `toAccount` | string \| null | Credited account (`ACC-XXXXX`). `null` for withdrawals. |
| `amount` | number | Positive, at most 2 decimals, no more than the currency's minor unit allows. |
| `currency` | string | ISO 4217 code, upper case. |
| `type` | string | `deposit`, `withdrawal` or `transfer`. |
| `timestamp` | string | ISO 8601 UTC instant the transaction was emitted. Defaults to the moment of creation. |
| `status` | string | `pending`, `completed` or `failed`. Defaults to `completed`. |

### Which accounts each type uses

| `type` | `fromAccount` | `toAccount` | Meaning |
|---|---|---|---|
| `deposit` | must be omitted | **required** | Money enters the ledger from outside. |
| `withdrawal` | **required** | must be omitted | Money leaves the ledger. |
| `transfer` | **required** | **required**, different from `fromAccount` | Money moves between two accounts. |

Sending `fromAccount` on a deposit is a validation error rather than a silently
ignored field: the two account fields are what make the balance arithmetic
unambiguous, so guessing the client's intent would risk mis-stating a balance.

## Endpoints

### Create a transaction

```
POST /transactions
```

Records a transaction. `id` is generated, `timestamp` defaults to now and
`status` defaults to `completed`.

**Body**

| Field | Required | Notes |
|---|---|---|
| `type` | yes | `deposit` \| `withdrawal` \| `transfer` |
| `amount` | yes | positive number, ≤ 2 decimals |
| `currency` | yes | ISO 4217 code |
| `fromAccount` | depends on `type` | see [the table above](#which-accounts-each-type-uses) |
| `toAccount` | depends on `type` | see [the table above](#which-accounts-each-type-uses) |
| `timestamp` | no | ISO 8601; defaults to now |
| `status` | no | `pending` \| `completed` \| `failed`; defaults to `completed` |

**Responses** — `201 Created` with the transaction and a `Location` header ·
`400` validation failed · `415` wrong content type

```bash
curl -X POST http://localhost:3000/transactions \
  -H "Content-Type: application/json" \
  -d '{"toAccount":"ACC-12345","amount":2500.00,"currency":"USD","type":"deposit"}'
```

```json
{
  "id": "8b2f1e5c-4a3d-4f9b-9c1e-2d7a6b5c4e3f",
  "fromAccount": null,
  "toAccount": "ACC-12345",
  "amount": 2500,
  "currency": "USD",
  "type": "deposit",
  "timestamp": "2026-09-09T07:38:55.368Z",
  "status": "completed"
}
```

### List transactions

```
GET /transactions
```

Returns a JSON array of transactions, newest first. All filters are optional and
can be combined; every filter is validated, so a typo returns `400` instead of an
empty list.

| Parameter | Format | Description |
|---|---|---|
| `accountId` | `ACC-XXXXX` | Transactions where the account is on **either** side. |
| `type` | enum | `deposit` \| `withdrawal` \| `transfer` |
| `from` | date or datetime | Inclusive lower bound on `timestamp`. A bare date starts at `00:00:00Z`. |
| `to` | date or datetime | Inclusive upper bound. A bare date ends at `23:59:59.999Z`. |
| `status` | enum | `pending` \| `completed` \| `failed` *(extra, beyond the assignment)* |
| `currency` | ISO 4217 | Single currency *(extra, beyond the assignment)* |

**Responses** — `200 OK` (possibly `[]`) · `400` invalid filter value, `to`
earlier than `from`, or a repeated parameter

```bash
curl "http://localhost:3000/transactions?accountId=ACC-12345&type=transfer&from=2024-01-01&to=2024-01-31"
```

```json
[
  {
    "id": "01483758-beee-4955-895e-a7f7b62139ca",
    "fromAccount": "ACC-67890",
    "toAccount": "ACC-12345",
    "amount": 300.25,
    "currency": "USD",
    "type": "transfer",
    "timestamp": "2024-01-14T16:45:00.000Z",
    "status": "completed"
  }
]
```

### Export transactions

```
GET /transactions/export?format=csv
```

Exports the ledger as RFC 4180 CSV (header row, `CRLF` line endings, quoted
fields where needed). **Accepts the same filters as
[`GET /transactions`](#list-transactions)**, so an export can be scoped to one
account or period.

| Parameter | Default | Description |
|---|---|---|
| `format` | `csv` | `csv` or `json`. Anything else is `400`. |
| *filters* | — | `accountId`, `type`, `from`, `to`, `status`, `currency` |

Amounts are written with the currency's own precision (`100.50`, `15000` for JPY)
so spreadsheets keep the cents. Unused account columns are empty rather than
`null`.

**Responses** — `200 OK` with `Content-Type: text/csv; charset=utf-8` and
`Content-Disposition: attachment; filename="transactions-YYYY-MM-DD.csv"` ·
`400` unsupported format or invalid filter

```bash
curl "http://localhost:3000/transactions/export?format=csv&accountId=ACC-12345"
```

```csv
id,fromAccount,toAccount,amount,currency,type,timestamp,status
b7b1e9dd-...,ACC-12345,ACC-A1B2C,75.00,USD,transfer,2024-01-20T10:30:00.000Z,pending
01483758-...,ACC-67890,ACC-12345,300.25,USD,transfer,2024-01-14T16:45:00.000Z,completed
```

### Retrieve an account balance

```
GET /accounts/:accountId/balance
```

Balance derived from **completed** transactions: deposits and incoming transfers
are credits, withdrawals and outgoing transfers are debits.

| Parameter | Description |
|---|---|
| `currency` | Optional. Returns a single-currency object instead of the per-currency list. |

**Responses** — `200 OK` · `400` malformed account number or currency ·
`404` unknown account

```bash
curl http://localhost:3000/accounts/ACC-12345/balance
```

```json
{
  "accountId": "ACC-12345",
  "balances": [
    { "currency": "JPY", "balance": 15000, "credits": 15000, "debits": 0, "transactionCount": 1 },
    { "currency": "USD", "balance": 4949.75, "credits": 5300.25, "debits": 350.5, "transactionCount": 4 }
  ],
  "asOf": "2026-09-09T07:38:55.392Z"
}
```

```bash
curl "http://localhost:3000/accounts/ACC-12345/balance?currency=USD"
```

```json
{
  "accountId": "ACC-12345",
  "currency": "USD",
  "balance": 4949.75,
  "credits": 5300.25,
  "debits": 350.5,
  "transactionCount": 4,
  "asOf": "2026-09-09T07:38:55.405Z"
}
```

An account with no completed transactions returns `"balances": []`; asking for a
specific `currency` the account has never used returns a zero balance.

### Retrieve an account summary

```
GET /accounts/:accountId/summary
```

Activity overview for an account: totals per currency plus counts across all
statuses.

| Parameter | Description |
|---|---|
| `currency` | Optional. Restricts `totals` to one currency. |

| Response field | Description |
|---|---|
| `transactionCount` | Transactions touching the account, **all statuses**. |
| `mostRecentTransactionDate` | `timestamp` of the newest transaction, any status. |
| `statusBreakdown` | Counts per `completed` / `pending` / `failed`. |
| `totals[]` | Per currency, over completed transactions: `totalDeposits`, `totalWithdrawals`, `totalTransfersIn`, `totalTransfersOut`, `netChange`, `transactionCount`, `mostRecentTransactionDate`. |

**Responses** — `200 OK` · `400` malformed account number · `404` unknown account

```bash
curl http://localhost:3000/accounts/ACC-67890/summary
```

```json
{
  "accountId": "ACC-67890",
  "transactionCount": 3,
  "mostRecentTransactionDate": "2024-01-14T16:45:00.000Z",
  "statusBreakdown": { "completed": 3, "pending": 0, "failed": 0 },
  "totals": [
    {
      "currency": "USD",
      "totalDeposits": 1200,
      "totalWithdrawals": 0,
      "totalTransfersIn": 100.5,
      "totalTransfersOut": 300.25,
      "netChange": 1000.25,
      "transactionCount": 3,
      "mostRecentTransactionDate": "2024-01-14T16:45:00.000Z"
    }
  ],
  "asOf": "2026-09-09T07:38:55.433Z"
}
```

### Calculate simple interest

```
GET /accounts/:accountId/interest?rate=0.05&days=30
```

Simple (non-compounding) interest on the current balance:

```
interest = balance × rate × days / 365
```

The result is rounded to the currency's minor unit, half away from zero. An
overdrawn balance yields negative interest.

| Parameter | Required | Description |
|---|---|---|
| `rate` | yes | Annual rate as a decimal fraction between 0 and 1 (`0.05` = 5%). |
| `days` | yes | Positive whole number of days, ≤ 36500. |
| `currency` | only when ambiguous | Required when the account holds more than one currency. |

**Responses** — `200 OK` · `400` invalid `rate`/`days`, or a multi-currency
account without `currency` · `404` unknown account

```bash
curl "http://localhost:3000/accounts/ACC-67890/interest?rate=0.05&days=30"
```

```json
{
  "accountId": "ACC-67890",
  "currency": "USD",
  "principal": 1000.25,
  "annualRate": 0.05,
  "days": 30,
  "dayCountBasis": 365,
  "interest": 4.11,
  "projectedBalance": 1004.36,
  "asOf": "2026-09-09T07:38:55.443Z"
}
```

### Service index and health

```
GET /
GET /health
```

`GET /` returns the API name, version, every endpoint with a one-line
description, and the accepted values for `type`, `status` and `currency` — the
fastest way to discover the API without leaving the terminal.

`GET /health` returns `{ "status": "ok", "uptimeSeconds": 12.3, "transactionCount": 10 }`
and is what `demo/run.sh` and `demo/capture-evidence.sh` poll while starting up.
